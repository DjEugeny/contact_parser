# Тест асинхронных провайдеров и кеширования

**Дата создания**: 2024-12-20 14:45 (UTC+07)  
**Цель**: Проверка работы асинхронных провайдеров LLM и системы кеширования

## 🎯 Тестируемые компоненты

### 1. AsyncProviderWrapper
- Асинхронные запросы к LLM провайдерам
- Статистика запросов (успешные, ошибки, время ответа)
- Интеграция с системой кеширования
- Обработка ошибок и retry-логика

### 2. AsyncProviderManager
- Управление несколькими асинхронными провайдерами
- Балансировка нагрузки между провайдерами
- Fallback механизмы при недоступности провайдера

### 3. Кеширование
- Сохранение результатов LLM запросов
- Статистика cache hits/misses
- Генерация ключей кеша на основе запросов

## 🧪 Тестовые сценарии

### Сценарий 1: Базовая функциональность
```python
# Тест создания асинхронного провайдера
async_wrapper = AsyncProviderWrapper(
    provider_config=openrouter_config,
    enable_cache=True
)

# Тест асинхронного запроса
response = await async_wrapper.make_request_async(
    prompt="Извлеки контакты из текста: Иван Петров, ivan@example.com",
    max_tokens=500
)
```

### Сценарий 2: Кеширование
```python
# Первый запрос - должен попасть в кеш
response1 = await async_wrapper.make_request_async(prompt="Тест")

# Второй идентичный запрос - должен взяться из кеша
response2 = await async_wrapper.make_request_async(prompt="Тест")

# Проверка статистики кеша
stats = async_wrapper.get_stats()
assert stats['cache_hits'] > 0
```

### Сценарий 3: Менеджер провайдеров
```python
# Тест создания менеджера с несколькими провайдерами
manager = AsyncProviderManager()
manager.add_provider('openrouter', openrouter_wrapper)
manager.add_provider('groq', groq_wrapper)

# Тест параллельной обработки
tasks = [
    manager.process_request(f"Запрос {i}")
    for i in range(10)
]
results = await asyncio.gather(*tasks)
```

## 📊 Ожидаемые результаты

### Производительность
- Асинхронные запросы должны выполняться параллельно
- Время обработки 10 запросов < времени 10 последовательных запросов
- Cache hit rate > 0% при повторных запросах

### Надежность
- Обработка ошибок сети и API
- Retry-логика при временных сбоях
- Fallback на другие провайдеры при недоступности

### Кеширование
- Корректное сохранение и извлечение из кеша
- Генерация уникальных ключей для разных запросов
- Статистика cache hits/misses

## 🚨 Возможные проблемы

### Технические риски
- Rate limiting от API провайдеров
- Проблемы с сетевым соединением
- Переполнение памяти при большом кеше
- Конфликты при параллельном доступе к кешу

### Решения
- Настройка лимитов запросов в секунду
- Retry-логика с экспоненциальной задержкой
- Ограничение размера кеша и TTL
- Thread-safe операции с кешем
