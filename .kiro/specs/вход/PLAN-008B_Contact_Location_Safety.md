
# TASK-008B: Contact Location Safety (запрет HQ‑протечек + явные правила)

**Цель:**
- Предотвращаем ложное обогащение `contacts.city/address` из HQ‑блоков организации; пишем город/адрес контакту **только** при явном персональном сигнале.
- Запретить автоперенос HQ‑адресов/городов в контакты.
- Разрешить локацию контакта **только** по явным персональным сигналам (подпись/тело письма рядом с ФИО/должностью).
- Внутренние сотрудники (домен нашей компании) **без** персонального сигнала → `city=address=null`.

## Преамбула проблемы
В текущем пайплайне контакты иногда получают **неперсональные HQ‑адрес/город** организации (из блока реквизитов), как будто это их личные данные. Нужно запретить такие «протечки» и заполнять `contacts.city/address` **только при явных персональных сигналах** (подпись/тело письма рядом с ФИО/должностью).

Сразу **после** `org_location_enrichment()` и **до** финальной нормализации:  
`... → org_location_enrichment → **contact_location_safety.extract()** → apply() → ...`

> Внедряется в существующий `contact_enricher.py` как новый «персональный локейшн‑блок» (не меняя логику ИНН/доменов).

## 1) Инварианты

- `contact.city/address` задаём только при **явном персональном сигнале** в подписи/теле этого контакта.
- Любые адреса/города из **организационного блока** (ИНН/ОГРН/общий адрес/сайт) — **нельзя** копировать в контакт.
- Внутренние сотрудники (домен нашей компании): если персонального сигнала нет → `city=address=null` (никаких автоподстановок).

---

## 2) Источники персональных сигналов

- Блок подписи с ФИО/должностью контакта; рядом персональные телефоны/e‑mail.
- Маркеры: `г.`, `город`, `регион`, «представитель», «офис в».  
- Неперсональные маркеры рядом с юр. реквизитами организации — игнорировать.

---

## 3) API и реализация

### 3.1 `extract_contact_location_evidence(message, signature_blocks_by_person) -> Dict[contact_gid, Evidence]`
- Возвращает для каждого контакта опциональные `{city?, address?, snippet, confidence}` — **только** если персонально.

### 3.2 `apply_contact_location(contact, evidence)`
- Пишем `city/address` **только если поле пусто**.
- Не перезаписываем ранее заполненные значения.
- В `postprocessing_metadata.location_evidence[contact_gid]` добавляем запись с `applied` и `snippet`.

### 3.3 Эвристики разделения персонального и HQ‑блока
- Если строка содержит `ИНН|ОГРН|р/с|к/с|БИК|ОКПО` — это HQ‑блок; адреса рядом считаем **корпоративными**, не персональными.
- Если рядом упоминается название организации — также считать корпоративным.
- Если строка содержит «Региональный представитель|офис в|территориальный менеджер» + `г./город` — это персональный сигнал.

## 4) Псевдокод

```python
for c in contacts:
    ev = extract_contact_location_evidence(msg, signatures.get(c.gid))
    if ev:
        if not c.city and ev.city:
            c.city = ev.city
        if not c.address and ev.address:
            c.address = ev.address
        metadata.location_evidence[c.gid].append({"applied": True, **ev})
    else:
        # ничего не делаем; НЕ копируем из HQ
        pass
```

## 5) Конфликты и защита от регресса

- Если у контакта уже есть `city` (например, «Новосибирск»), а новая обработка нашла «Москва» **без** персонального сигнала — **игнорировать** новое.
- Никаких backfill для контактов из вложений организации (вложения → только для **организаций**, см. TASK‑008A).
