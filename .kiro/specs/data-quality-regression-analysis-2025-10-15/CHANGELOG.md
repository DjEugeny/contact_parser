# 📋 Changelog: Исправление деградации качества данных

## [CRITICAL FIX] 2025-10-15 - Восстановление качества извлечения данных

### 🔴 Критическое исправление

**Проблема:** После рефакторинга Email Fetcher качество извлечения данных LLM упало на 60-80% из-за несовместимости структуры данных.

**Корневая причина:** `api_pipeline_validator.py` искал только устаревшее поле `"body"`, которого нет в новом формате данных от рефакторенного fetcher.

**Решение:** Добавлена fallback логика для поддержки всех форматов полей body.

---

### 📝 Изменения в коде

#### Изменённые файлы

**`src/api_pipeline_validator.py`**
- **Метод:** `_compose_combined_text()` (строки 667-697)
- **Изменение:** Заменён прямой доступ к `email_data.get("body")` на fallback логику
- **Резервная копия:** `src/api_pipeline_validator.py.backup-2025-10-15`

**До исправления:**
```python
body = email_data.get("body")  # ❌ Только legacy формат
if body:
    parts.append(f"=== ТЕКСТ ПИСЬМА ===\n{body}")
```

**После исправления:**
```python
# ✅ Поддержка legacy + NEW форматов
body_candidates = [
    email_data.get("body"),          # legacy
    email_data.get("body_clean"),    # NEW (приоритет)
    email_data.get("body_raw"),      # NEW (fallback)
    email_data.get("body_plain"),
    email_data.get("body_text"),
    email_data.get("text"),
]

body = None
body_source = None
for candidate_name, candidate in zip(...):
    if candidate and isinstance(candidate, str) and candidate.strip():
        body = candidate
        body_source = candidate_name
        break

if body:
    print(f"✅ Использовано поле: '{body_source}', длина: {len(body)} символов")
    parts.append(f"=== ТЕКСТ ПИСЬМА ===\n{body}")
else:
    print(f"⚠️ Тело письма не найдено! Доступные поля: {list(email_data.keys())}")
```
