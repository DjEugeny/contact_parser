## 📋 Резюме

После рефакторинга модуля `advanced_email_fetcher.py` → `src/fetcher/` произошла **критическая деградация качества** извлечения данных LLM. Качество упало на **60-80%** по всем метрикам.

### Основная причина

**Несовместимость структуры данных между Email Fetcher и API Pipeline Validator**

- **Legacy fetcher** создаёт поле: `"body"`
- **New fetcher** создаёт поля: `"body_raw"` и `"body_clean"`, **но НЕ создаёт** `"body"`
- **api_pipeline_validator.py** ищет **только** поле `"body"` (строка 670)
- **Результат:** текст письма НЕ передаётся в LLM → деградация качества

#### New Fetcher (новый)

**Примечание:** `char_count` в новой версии значительно меньше из-за агрессивной очистки в `body_clean`.

### 2. Проблемное место в коде

**Файл:** `src/api_pipeline_validator.py`  
**Строка:** 670  
**Метод:** `_compose_combined_text()`

```python
def _compose_combined_text(self, email_data: Dict[str, Any], date: str) -> str:
    """📝 Собирает текст письма и извлечённые файлы вложений."""
    parts: List[str] = []
    body = email_data.get("body")  # ❌ ИЩЕТ ТОЛЬКО СТАРОЕ ПОЛЕ!
    if body:
        parts.append(f"=== ТЕКСТ ПИСЬМА ===\n{body}")
    # ... остальной код
```

**Что происходит:**
1. `email_data.get("body")` → `None` (поля нет в новом fetcher)
2. Условие `if body:` → `False`
3. Текст письма **НЕ добавляется** в `combined_text`
4. LLM получает **только вложения** без контекста письма
5. Качество резко падает

### 3. Правильная реализация (уже есть в file_tokens.py)

**Файл:** `src/utils/file_tokens.py`  
**Строка:** 206-217

```python
def _extract_email_body(self, email_data: Dict[str, Any]) -> str:
    """📝 Извлекает тело письма с учётом возможных вариантов полей."""
    body_candidates = [
        email_data.get("body"),          # legacy
        email_data.get("body_clean"),    # NEW ✅
        email_data.get("body_plain"),
        email_data.get("body_text"),
        email_data.get("text"),
        email_data.get("body_raw"),      # NEW ✅
    ]
    
    for candidate in body_candidates:
        if candidate and isinstance(candidate, str) and candidate.strip():
            return candidate
    return ""
```

## 🎯 Корневая причина (Root Cause)

### Цепочка проблемы

1. **Email Fetcher (новый)** создаёт `body_raw` и `body_clean`
2. **api_pipeline_validator.py** ищет `body` (устаревшее поле)
3. Поле не найдено → `body = None`
4. Текст письма НЕ добавляется в `combined_text`
5. **LLM получает только вложения БЕЗ контекста**
6. LLM не может правильно извлечь:
   - Полные имена (они в подписи письма)
   - Должности (они в подписи письма)
   - Телефоны (они в подписи письма)
   - Адреса (они в подписи письма)
7. **Результат:** деградация качества на 60-80%

### Почему file_tokens.py работает правильно?

В `src/utils/file_tokens.py` уже реализована **правильная fallback логика**:

```python
body_candidates = [
    email_data.get("body"),          # legacy
    email_data.get("body_clean"),    # NEW
    email_data.get("body_plain"),
    email_data.get("body_text"),
    email_data.get("text"),
    email_data.get("body_raw"),      # NEW
]
```

Она проверяет **все возможные варианты** полей и берёт первое непустое.

## 🛠️ Решение

### Вариант 1: Минимальное исправление (рекомендуется)

Добавить fallback логику в `api_pipeline_validator.py`:

```python
def _compose_combined_text(self, email_data: Dict[str, Any], date: str) -> str:
    """📝 Собирает текст письма и извлечённые файлы вложений."""
    parts: List[str] = []
    
    # ✅ ИСПРАВЛЕНИЕ: Поддержка новой структуры данных
    body_candidates = [
        email_data.get("body"),          # legacy
        email_data.get("body_clean"),    # NEW (приоритет выше)
        email_data.get("body_raw"),      # NEW (fallback)
        email_data.get("body_plain"),
        email_data.get("body_text"),
        email_data.get("text"),
    ]
    
    body = None
    for candidate in body_candidates:
        if candidate and isinstance(candidate, str) and candidate.strip():
            body = candidate
            break
    
    if body:
        parts.append(f"=== ТЕКСТ ПИСЬМА ===\n{body}")
    
    # ... остальной код без изменений
```
