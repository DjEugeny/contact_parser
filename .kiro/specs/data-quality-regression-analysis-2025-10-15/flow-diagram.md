## 🔑 Ключевые выводы

### Почему body_clean короче body?

**Legacy body (5490 символов):**
- Содержит весь текст с HTML-тегами: `<tel:+74994900272>`, `<mailto:...>`
- Повторы из цитирования предыдущих писем
- Форматирование и переносы строк

**NEW body_clean (2449 символов):**
- HTML-теги удалены: `<tel:...>` → текст чище
- Агрессивная очистка от повторов
- Нормализация пробелов

**Важно:** Несмотря на меньший размер, `body_clean` содержит **все критичные данные**:
- ✅ Имена
- ✅ Должности  
- ✅ Телефоны (как текст)
- ✅ Адреса
- ✅ Email

### Почему без body LLM теряет данные?

LLM получает **только PDF вложение** без контекста:
- PDF содержит: КП с ценами, оборудованием
- PDF **НЕ содержит**: подписи отправителей с контактами

**Контакты находятся в подписях писем!**

Без текста письма LLM:
- ❌ Не видит полные имена (видит только email)
- ❌ Не видит должности
- ❌ Не видит прямые телефоны
- ❌ Не видит адреса офисов
- ❌ Теряет контекст диалога

## 🎯 Решение: Fallback логика

```python
# ✅ ПРАВИЛЬНО: Проверяем все варианты
body_candidates = [
    email_data.get("body"),          # Для legacy compatibility
    email_data.get("body_clean"),    # Приоритет: очищенный текст
    email_data.get("body_raw"),      # Fallback: сырой текст
    email_data.get("body_plain"),    # Альтернативы
    email_data.get("body_text"),
    email_data.get("text"),
]

for candidate in body_candidates:
    if candidate and isinstance(candidate, str) and candidate.strip():
        body = candidate
        break  # Берём первый найденный
```

**Преимущества:**
- ✅ Работает с legacy форматом
- ✅ Работает с новым форматом
- ✅ Защита от будущих изменений
- ✅ Явный приоритет: clean → raw → other
