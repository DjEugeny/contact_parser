### 1. Фильтр получателей (Пункт 5 из analysis-report.md)

**Исследование:** Отсутствие путей к вложениям

**Гипотеза подтверждена:** Да, частично. Проблема в двух местах:

#### Проблема A: Фильтр массовой рассылки
**Найдено:** `src/advanced_email_fetcher.py:346`
```python
if internal_recipients >= 10:
    return f"массовая внутренняя рассылка ({internal_recipients} получателей)"
```

**Текущее поведение:**
- Фильтр отсекает ВСЕ письма с 10+ получателями `@dna-technology.ru`
- Даже если письмо от внешнего отправителя
- Даже если s.voronova@dna-technology.ru - один из многих получателей

**Требуемое поведение:**
- Фильтр должен срабатывать ТОЛЬКО для внутренних рассылок:
  - Отправитель `@dna-technology.ru` И
  - Все получатели `@dna-technology.ru` И
  - Количество >= 10
- Внешние письма НЕ должны фильтроваться по количеству получателей

**Решение:**
1. Вынести порог `10` в `config/settings.py`
2. Изменить логику проверки (см. Задачу 1.4 в action-plan.md)
3. Добавить unit-тесты

**Приоритет:** 🟠 ВЫСОКИЙ  
**Срок:** 1-2 дня

#### Проблема B: Вложения не сохранялись из-за фильтров
**Найдено:** Вложения показаны в разделе `attachments` JSON файла письма, но не были сохранены физически.

**Причины:**
- Фильтры по расширениям (`EXCLUDED_EXTENSIONS`)
- Фильтры по именам файлов (`attachment_filename_excludes.txt`)
- Фильтры inline изображений
- Фильтры по размеру

**Решение:** Уже реализовано в коде, дополнительных действий не требуется.

### 2. JSON Schema валидация (Пункт 3 из analysis-report.md)

**Исследование:** Насколько критична проблема?

**Текущая ситуация:**
- Автокоррекция работает и исправляет ошибки
- 6 из 30 писем (20%) требуют автокоррекции
- Типичные ошибки:
  - `None` вместо integer для `contact_id`, `organization_id`
  - Неправильные enum значения (`info_request` вместо `clarification`)

**Риски если оставить на автокоррекцию:**
- ❌ Неправильные связи между сущностями (низкий риск)
- ❌ Потеря семантической точности (средний риск)
- ❌ Накопление технического долга (низкий риск)
- ❌ Сложность отладки при масштабировании (средний риск)

**Преимущества улучшения промпта:**
- ✅ Более точные данные с первого раза
- ✅ Меньше нагрузки на автокоррекцию
- ✅ Лучшая предсказуемость результатов
- ✅ Снижение ошибок с 20% до <5%

**Вывод:** Не критично, но желательно улучшить промпт.

**Приоритет:** 🟡 СРЕДНИЙ (понижен с ВЫСОКОГО)  
**Срок:** 3 дня
