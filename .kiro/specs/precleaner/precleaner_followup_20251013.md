# PreCleaner: письмо HimLabService (2025-10-13)

## Контекст
- Проверено письмо `data/emails/2025-04-01/email_016_20250401_20250401_himlabservice_ru_06d4360a.json` и исходный `.eml` (`data/eml/2025-04-01/70131743503110_mail.yandex.ru_205758_421727.eml`).
- После последних изменений в ядре PreCleaner ожидалось, что `body_clean` сохраняет только актуальный ответ с одной подписью и placeholders для цитат.
- Фактический JSON содержит длинную, однострочную версию тела (~36k знаков) и повторяющиеся блоки с подписью `C Уважением, …`, что ломает фильтрацию.

## Наблюдения
- В сохранённом JSON `body_clean` не содержит переводов строк (`'\n' not in body_clean`), а длина 36160 символов — это почти исходный HTML после грубой нормализации.
- `body_raw` совпадает с «сплющенным» текстом, значит на этапе сохранения результат PreCleaner не был применён (или вернулся fallback).
- Запуск рабочего конвейера на `.eml` локально (`EmailParser → EnhancedTextCleanerWithPreCleaner`) даёт `body_clean` длиной 11 030 символов, с placeholders `[quoted message elided …]` и единственной подписью Татьяны Сунцовой: регресс не воспроизводится при прямом прогоне.
- Конфиг `config/precleaner.yaml` не содержит латинского маркера `c уважением`, поэтому fallback-конвейер без PreCleaner не сможет детектировать подпись, если строки ещё не нормализованы.
- Поле `eml_path` в JSON указывает на `..._195825_217221.eml`, которого нет в `data/eml/2025-04-01/` (актуальный файл заканчивается на `_205758_421727.eml`). Регрессионный скрипт ищет старые пути и падает.

## Гипотезы и риски
- Основной сценарий: при прошлой переработке письма PreCleaner упал (или был отключён), и адаптер вернул исходный текст без сегментации. Это объясняет отсутствие перевода строк и сохранение подписи.
- Латинская «C» в подписи не покрывается текущими сигнатурами, поэтому даже при успешном проходе базового очистителя может остаться «грязная» подпись, если PreCleaner не задействован.
- Несостыковка путей `.eml` указывает на частичную миграцию: JSON и эмлы сохранялись разными версиями fetcher. Пока это не починить, регрессионные тесты останутся «красными».
- Риск регресса: любое усиление сигнатур или жёсткое удаление блоков может снова вырезать полезные контакты внутри цитат (что мы уже чинили). Нужно подтверждать изменения на всём наборе 2025‑04‑01.
