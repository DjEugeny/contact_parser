## 🔴 Критические проблемы

### 1. **Ошибка импорта OCR модуля** (УСТАРЕВШАЯ ОЦЕНКА)
**Серьёзность**: 🟡 Средняя (переоценка после углублённого анализа)  
**Локация**: Строка 449

**⚠️ ОБНОВЛЕНИЕ**: Углублённый анализ показал, что это НЕ критическая проблема!

**Реальная ситуация**:
- OCR кеш уже содержит результаты для большинства файлов
- Проблема: кеш НЕ НАХОДИТ существующие результаты из-за несовпадения хешей в именах файлов
- Письмо #10: файл `20250827_20081ed0_...pdf` ищется в кеше, но результат существует как `20250827_38ae8d4c_...txt`

**Root Cause** (детали в ROOT_CAUSE_ANALYSIS_PART1.md):
1. Fetcher при повторном сохранении создаёт новый хеш (зависит от timestamp)
2. OCRCacheManager ищет по ПОЛНОМУ имени файла (включая хеш)
3. Хеш не совпадает → кеш промах → попытка запустить OCR
4. OCR падает с ошибкой импорта (которая маскирует реальную проблему)

**Решение**: Исправить поиск в OCRCacheManager (поиск по оригинальному имени без хеша)

**Влияние на пайплайн**: Среднее - OCR кеш не используется, но данные НЕ теряются (они уже есть)

### 2. **JSON Schema валидация: organization_id = None** (УТОЧНЁННАЯ ОЦЕНКА)
**Серьёзность**: 🔴 Критическая (системная ошибка дизайна)  
**Количество случаев**: 8 из 27 писем (30%)

```
❌ JSON Schema валидация не прошла: None is not of type 'integer'
🔧 Установлено значение по умолчанию для contact 0 organization_id: 1
⚠️ Контакт unknown (Кузнецова Ирина Андреевна): организация 1 не найдена
```

**🔬 ROOT CAUSE** (детальный анализ в ROOT_CAUSE_ANALYSIS_PART1.md):

1. **LLM работает ПРАВИЛЬНО**: Возвращает `organization_id: null` для писем БЕЗ организаций
   - Пример: личное письмо о бронировании билетов (email_001_20250828)
   - От: `anda4@yandex.ru` (публичный почтовик)
   - Нет упоминания компаний, нет корпоративных email

2. **Автокоррекция работает НЕПРАВИЛЬНО** (`safe_math_utils.py:171`):
   ```python
   data[key] = 1  # ❌ ХАРДКОД: всегда подставляет 1
   ```
   - Не проверяет, существует ли организация с ID=1
   - Создаёт фантомные связи

3. **Промпт v1.1 создаёт НЕВЫПОЛНИМОЕ требование**:
   ```
   organization_id - ВСЕГДА число (1, 2, 3...)
   ```
   - Что делать для писем БЕЗ организаций?
   - LLM вынужден нарушать правило или придумывать фиктивные организации

4. **Последствия**:
   - organizations[] = пусто
   - contacts[].organization_id = 1 (несуществующий)
   - GID не назначаются (нет org_gid для организации 1)
   - Контакты остаются с `"contact_gid": "unknown"`

**Количество затронутых писем**: 
- Цикл 1 (2025-08-27): 5/18 писем (28%)
- Цикл 2 (2025-08-28): 3/9 писем (33%)

**Влияние на пайплайн**: 🔴 КРИТИЧЕСКОЕ
- Данные контактов сохраняются, но теряется структура связей
- Невозможно обогащение (enrichment) контактов
- GID не назначаются → проблемы с дедупликацией
- 30% писем затронуты

**Решение**: См. ROOT_CAUSE_ANALYSIS_PART2.md (Этап 2)
