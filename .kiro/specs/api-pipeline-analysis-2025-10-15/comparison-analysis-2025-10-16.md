## 🔥 Критические проблемы

### 1. **Регрессия в валидации JSON Schema** 🔴 P0

**Суть**: Появились 3 новых ошибки валидации, которых не было раньше.

**Примеры**:
```
❌ None is not of type 'integer' (contact_id в interactions)
❌ None is not of type 'string' (неизвестное поле)
```

**Root cause**: 
- Промпт v1.2 разрешает `organization_id: null`
- Но JSON Schema не разрешает `null` для **других полей** (contact_id, возможно phone/email)
- Автокоррекция всё ещё активна и маскирует проблему

**Влияние**: 
- Данные искажаются автокоррекцией (`contact_id=1` для несуществующих контактов)
- Валидация не отражает реальную структуру LLM-ответов

**Решение**: 
1. Пройтись по всей JSON Schema в `src/core/validator.py`
2. Найти все поля с `type: "integer"` или `type: "string"` без `null`
3. Разрешить `null` для опциональных полей (contact_id, organization_id, phone, email и т.д.)
4. Убрать автокоррекцию для этих полей в `src/core/safe_math_utils.py`

**Время**: 2-3 часа

def _get_attachment_text(self, attachment, email_data):
