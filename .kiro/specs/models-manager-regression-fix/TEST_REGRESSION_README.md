# 🧪 Регрессионный тест ModelsManager

## Описание

Тестовый скрипт `test_regression_fix.py` предназначен для проверки исправления регрессии в ModelsManager при обработке писем от 2025-07-28.

## Что проверяет тест

Скрипт загружает 7 писем от 2025-07-28 и обрабатывает их через полный pipeline, собирая следующие метрики:

### Метрики

1. **success_rate** - процент успешно обработанных писем
2. **empty_responses** - количество пустых ответов от LLM
3. **errors** - количество критических ошибок
4. **total_contacts** - общее количество извлеченных контактов
5. **total_organizations** - общее количество извлеченных организаций

### Требования (Requirements)

Тест проверяет выполнение следующих требований:

- **7.1**: Все письма обработаны (processed_emails == total_emails)
- **7.2**: Success rate >= 80%
- **7.3**: Пустых ответов <= 1
- **7.4**: Критических ошибок = 0
- **7.5**: Извлечены контакты (total_contacts > 0)

## Использование

### Запуск теста

```bash
python test_regression_fix.py
```

### Результаты

Скрипт выводит:
1. Детальный лог обработки каждого письма
2. Сводную статистику по метрикам
3. Проверку выполнения требований
4. Итоговый вердикт (PASS/FAIL)

Результаты также сохраняются в JSON файл:
```
data/test_reports/regression_test_YYYYMMDD_HHMMSS.json
```

### Код возврата

- `0` - все требования выполнены
- `1` - некоторые требования не выполнены

## Структура кода

### Классы

- **RegressionTestMetrics** - сборщик метрик для тестирования
  - `add_result()` - добавить результат обработки письма
  - `add_error()` - добавить ошибку
  - `calculate_success_rate()` - рассчитать процент успешности
  - `get_summary()` - получить сводку метрик

### Функции

- `print_header()` - вывести заголовок теста
- `load_test_emails()` - загрузить тестовые письма
- `process_emails_with_metrics()` - обработать письма и собрать метрики
- `print_detailed_report()` - вывести детальный отчет
- `save_report()` - сохранить отчет в файл
- `main()` - главная функция теста

## Зависимости

Скрипт использует следующие модули:
- `src.email_loader.ProcessedEmailLoader` - загрузка писем
- `src.integrated_llm_processor.IntegratedLLMProcessor` - обработка через pipeline

## Примечания

- Тест использует реальные LLM API (не тестовый режим)
- Обработка может занять несколько минут из-за rate limits
- Результаты зависят от доступности LLM провайдеров
- При rate limit происходит автоматическое переключение моделей

## Отладка

Если тест не проходит:

1. Проверьте наличие писем: `ls -la data/emails/2025-07-28/`
2. Проверьте конфигурацию моделей: `config/models_config.yaml`
3. Проверьте логи: `data/logs/model_fallback.log`
4. Проверьте отчет: `data/test_reports/regression_test_*.json`
