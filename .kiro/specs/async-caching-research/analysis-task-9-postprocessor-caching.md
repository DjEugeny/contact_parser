## 1. Обзор компонента INNCacheManager

INNCacheManager - это система кэширования для найденных ИНН организаций с поддержкой TTL (Time To Live), атомарных операций и валидации данных.

**Основные характеристики:**
- Формат хранения: JSONL (JSON Lines) - каждая строка содержит отдельную JSON-запись
- Механизм TTL: Настраиваемый срок жизни записей (по умолчанию 180 дней)
- Атомарность: Использование file locking (fcntl) для безопасных конкурентных операций
- Ключ кэша: MD5 хэш от комбинации name_norm|city_norm|domain

## 2. Структура данных кэша

### CacheEntry (dataclass)

```python
@dataclass
class CacheEntry:
    key: str              # MD5 хэш ключа кэша
    name_norm: str        # Нормализованное название организации
    city_norm: str        # Нормализованный город
    domain: str           # Домен организации
    inn: str              # Найденный ИНН
    source: str           # Источник данных (dadata, fns, etc.)
    score: float          # Скор доверия (0.0-1.0)
    checked_at: str       # ISO timestamp проверки
```

**Пример записи в JSONL:**
```json
{"key": "a1b2c3d4e5f6...", "name_norm": "ромашка", "city_norm": "москва", "domain": "romashka.ru", "inn": "7707123456", "source": "dadata", "score": 0.92, "checked_at": "2025-10-07T10:30:00"}
```

## 3. Основные методы INNCacheManager

### 3.1 `__init__(cache_path: Path, ttl_days: int = 180)`

Инициализация менеджера кэша:
- Создание директории и файла кэша при необходимости
- Настройка TTL (по умолчанию 180 дней)

### 3.2 `generate_cache_key(name_norm, city_norm, domain) -> str`

Генерация уникального ключа кэша:
- Использует MD5 хэш от строки name_norm|city_norm|domain
- Обеспечивает быстрый поиск по комбинации параметров

### 3.3 `get_cached_inn(name_norm, city_norm, domain) -> Optional[Dict]`

**Алгоритм работы:**
1. Генерирует ключ кэша из входных параметров
2. Открывает файл кэша с shared lock (LOCK_SH) для чтения
3. Построчно читает JSONL файл
4. Для каждой записи:
   - Парсит JSON
   - Проверяет совпадение ключа
   - Проверяет TTL через is_expired()
   - Если запись валидна и не истекла - возвращает данные
5. Освобождает lock

**Возвращаемые данные:**
```json
{
    'inn': '7707123456',
    'source': 'dadata',
    'score': 0.92,
    'checked_at': '2025-10-07T10:30:00'
}
```

**Особенности:**
- Линейный поиск по файлу (O(n))
- Автоматическая проверка TTL при чтении
- Graceful handling невалидных записей (логирование + пропуск)
- Thread-safe благодаря file locking

### 3.4 `save_to_cache(name_norm, city_norm, inn, source, score, domain) -> bool`

**Алгоритм работы:**
1. Генерирует ключ кэша
2. Создает объект CacheEntry с текущим timestamp
3. Открывает файл в режиме append с exclusive lock (LOCK_EX)
4. Записывает JSON-строку с переводом строки
5. Выполняет flush() и fsync() для гарантии записи на диск
6. Освобождает lock

**Особенности:**
- Append-only операция (не проверяет дубликаты)
- Атомарная запись с fsync для надежности
- Thread-safe и process-safe
- Не удаляет старые записи с тем же ключом (могут быть дубликаты)

### 3.5 `cleanup_expired_entries() -> int`

**Алгоритм работы:**
1. Читает весь файл кэша с shared lock
2. Фильтрует записи:
   - Валидные и не истекшие → сохраняет
   - Истекшие или невалидные → удаляет
3. Перезаписывает файл с exclusive lock только валидными записями
4. Возвращает количество удаленных записей

**Особенности:**
- Полная перезапись файла (может быть медленной для больших кэшей)
- Удаляет как истекшие, так и поврежденные записи
- Рекомендуется запускать периодически (например, раз в день)

### 3.6 `get_cache_stats() -> Dict[str, Any]`

**Возвращаемая статистика:**
```json
{
    'total_entries': 1523,
    'expired_entries': 45,
    'valid_entries': 1478,
    'cache_file_size': 245678,  # bytes
    'oldest_entry': '2024-04-07T10:30:00',
    'newest_entry': '2025-10-07T10:30:00'
}
```

## 4. Механизм TTL (Time To Live)

**Реализация в CacheEntry.is_expired()**
```python
def is_expired(self, ttl_days: int) -> bool:
    try:
        checked_date = datetime.fromisoformat(self.checked_at)
        return datetime.now() - checked_date > timedelta(days=ttl_days)
    except (ValueError, TypeError):
        return True  # Невалидная дата = истекшая запись
```

**Особенности:**
- Проверка при каждом чтении из кэша
- Истекшие записи игнорируются, но остаются в файле до cleanup
- Невалидные даты считаются истекшими (fail-safe подход)
- TTL настраивается при инициализации (по умолчанию 180 дней)

## 5. Атомарность и безопасность

### File Locking (fcntl)
- **LOCK_SH (Shared Lock):** Для чтения - несколько процессов могут читать одновременно
- **LOCK_EX (Exclusive Lock):** Для записи - эксклюзивный доступ
- **LOCK_UN (Unlock):** Явное освобождение блокировки

### Гарантии записи
```python
f.write(json.dumps(asdict(entry), ensure_ascii=False) + '\n')
f.flush()
os.fsync(f.fileno())  # Принудительная синхронизация с диском
```

**Защита от:**
- Race conditions при конкурентной записи
- Потери данных при сбое (fsync)
- Повреждения файла при одновременном доступе

## 7. Формат хранения JSONL

### Преимущества JSONL:
- ✅ Простота append операций (добавление в конец файла)
- ✅ Построчная обработка (не нужно загружать весь файл в память)
- ✅ Устойчивость к повреждениям (одна поврежденная строка не ломает весь файл)
- ✅ Человекочитаемый формат для отладки
- ✅ Легко обрабатывать стандартными утилитами (grep, awk, jq)

### Недостатки JSONL:
- ❌ Линейный поиск O(n) - медленно для больших объемов
- ❌ Возможны дубликаты (append-only без проверки)
- ❌ Cleanup требует полной перезаписи файла
- ❌ Нет индексации для быстрого поиска

## 8. Производительность и ограничения

### Текущие характеристики:
- **Поиск:** O(n) - линейный по количеству записей
- **Запись:** O(1) - append в конец файла
- **Cleanup:** O(n) - чтение + фильтрация + перезапись

### Потенциальные проблемы:
- **Масштабируемость:** При >100k записей поиск станет медленным
- **Дубликаты:** Append-only может создавать множественные записи для одного ключа
- **Cleanup overhead:** Полная перезапись файла блокирует доступ

### Рекомендации для улучшения:
- Использовать SQLite или Redis для индексированного доступа
- Добавить in-memory LRU кэш для горячих записей
- Реализовать партиционирование по первым символам хэша
- Добавить проверку дубликатов при записи
