## 4. Анализ метода connect() на блокирующие вызовы

### Результат: ⚠️ ПОЛНОСТЬЮ БЛОКИРУЮЩИЙ

**Код метода connect():**

```python
# Файл: src/advanced_email_fetcher.py, строки 699-725
def connect(self) -> bool:
    """🔌 Подключение к серверу"""
    max_attempts = 3
    for attempt in range(max_attempts):
        try:
            if self.mail:
                try:
                    self.mail.logout()  # БЛОКИРУЮЩИЙ ВЫЗОВ
                except:
                    pass

            self.logger.info(f"🔌 Подключение к {IMAP_SERVER} (попытка {attempt + 1}/{max_attempts})...")
            self.mail = imaplib.IMAP4(IMAP_SERVER, IMAP_PORT)  # БЛОКИРУЮЩИЙ ВЫЗОВ
            self.mail.starttls(ssl.create_default_context())    # БЛОКИРУЮЩИЙ ВЫЗОВ
            self.mail.login(IMAP_USER, IMAP_PASSWORD)           # БЛОКИРУЮЩИЙ ВЫЗОВ
            self.mail.select('INBOX')                           # БЛОКИРУЮЩИЙ ВЫЗОВ
            self.last_connect_time = time.time()
            self.logger.info(f"✅ Подключение успешно")
            return True

        except Exception as e:
            self.logger.error(f"❌ Ошибка подключения (попытка {attempt + 1}): {e}")
            if attempt < max_attempts - 1:
                time.sleep(RETRY_DELAY)  # БЛОКИРУЮЩАЯ ЗАДЕРЖКА (5 сек)

    return False
```

**Блокирующие операции:**
1. `imaplib.IMAP4()` - синхронное TCP подключение
2. `mail.starttls()` - синхронное TLS рукопожатие
3. `mail.login()` - синхронная аутентификация
4. `mail.select()` - синхронный выбор папки
5. `time.sleep(RETRY_DELAY)` - блокирует поток на 5 секунд при ошибке

**Проблемы:**
- При сетевых задержках весь процесс останавливается
- Повторные попытки блокируют выполнение (до 15 секунд: 3 попытки × 5 сек)
- Невозможно обрабатывать другие письма во время подключения

**Узкие места производительности:**

1. **Последовательная обработка:**
   - Одно письмо за раз
   - Невозможность параллельной загрузки

2. **Сетевые задержки:**
   - Каждый IMAP запрос ждет ответа сервера
   - Латентность сети умножается на количество писем

3. **Искусственные задержки:**
   - `REQUEST_DELAY = 0.5` сек между письмами
   - `RETRY_DELAY = 5` сек при ошибках

4. **Переподключения:**
   - Каждые 50 писем (`BATCH_SIZE`)
   - Блокирует обработку на время подключения
