# Предотвращение HQ-Backfill (TASK-008B)

## Проблема

После внедрения модуля `contact_location_safety`, который корректно определял персональные локационные сигналы, контакты **все равно** получали HQ-адреса организаций через метод `_backfill_contact_city_address`.

### Примеры проблемных кейсов:

**Email 017 - Клочкова-Абельянц Сатеник Аршавиловна:**
- **Raw (от LLM)**: `city: null, address: null` ✅ Правильно
- **Processed (после постобработки)**: `city: "Москва", address: "Москва, Варшавское шоссе..."` ❌ Ошибка!
- **Причина**: Backfill применил HQ-адрес организации ДНК-Технология

**Email 016 - Воронова С.С.:**
- **Raw (от LLM)**: `city: null, address: null` ✅ Правильно (нет персонального сигнала в подписи)
- **Processed**: Получила HQ-адрес ❌ Ошибка!

## Решение

### 1. Новая логика в `_backfill_contact_city_address`

Backfill теперь применяется **только** если у контакта уже есть персональная локация:

```python
# Проверяем, был ли контакт уже обработан contact_location_safety
has_personal_location = (
    _has_value(contact.get('city')) or 
    _has_value(contact.get('address'))
)

# Backfill применяется только если есть персональная локация
allow_backfill = has_personal_location

if not allow_backfill:
    logger.debug(
        f"Контакт {contact['name']} без персональной локации. "
        f"Backfill HQ-локации пропущен."
    )
```

### 2. Правила применения Backfill

| Ситуация | city | address | Backfill | Причина |
|----------|------|---------|----------|---------|
| Нет персонального сигнала | `null` | `null` | ❌ ЗАПРЕЩЕН | Предотвращение HQ-протечки |
| Есть персональный город | `"Новосибирск"` | `null` | ✅ РАЗРЕШЕН | Может дополнить address |
| Есть персональный адрес | `null` | `"ул. Ленина, 10"` | ✅ РАЗРЕШЕН | Может дополнить city |
| Оба поля заполнены | `"Москва"` | `"ул. Ленина, 10"` | ✅ РАЗРЕШЕН | Но не перезапишет |
| Пустые строки | `""` | `"   "` | ❌ ЗАПРЕЩЕН | Считается как отсутствие данных |

### 3. Метаданные

Для контактов, у которых backfill был пропущен, добавляется запись в provenance:

```json
{
  "contact_id": 4,
  "provenance": {
    "backfill_skipped": "no_personal_location_signal"
  }
}
```

## Результаты

### До изменений:
```json
{
  "name": "Клочкова-Абельянц Сатеник Аршавиловна",
  "email": null,
  "city": "Москва",  // ❌ HQ-протечка!
  "address": "Москва, Варшавское шоссе, дом 125Ж, корпус 6, этаж 5"  // ❌ HQ-протечка!
}
```

## Взаимодействие с contact_location_safety

1. **Этап 1**: `contact_location_safety` извлекает персональные локационные сигналы
2. **Этап 2**: Если найден персональный сигнал с достаточным confidence - применяет city/address
3. **Этап 3**: `_backfill_contact_city_address` проверяет наличие city/address
4. **Этап 4**: Если есть - может дополнить недостающее поле из организации
5. **Этап 5**: Если нет - backfill пропускается, предотвращая HQ-протечку

## Преимущества подхода

1. **Безопасность по умолчанию**: Контакты не получают HQ-адреса без явного персонального сигнала
2. **Гибкость**: Если у контакта есть город, но нет адреса - backfill может дополнить адрес
3. **Прозрачность**: Все решения логируются и сохраняются в метаданных
4. **Простота**: Логика понятна и легко тестируется
