## Ключевые особенности реализации

### 1. Confidence Scoring (Оценка уверенности)

Шкала confidence:
- **0.9-1.0**: Очень высокая (сильные персональные маркеры: "представитель в", "офис в")
- **0.8-0.9**: Высокая (подпись с ФИО и должностью)
- **0.7-0.8**: Средняя (подпись с локационными маркерами)
- **0.6-0.7**: Низкая (упоминание в теле без контекста)
- **0.0**: HQ-блок (не применяется)

### 2. Защита от HQ-протечек

**Определение HQ-блоков:**
- Наличие юридических маркеров: ИНН, ОГРН, р/с, к/с, БИК, ОКПО
- Адрес рядом с названием организации без персонального контекста

**Правила применения:**
- Только если поле пустое (не перезаписываем существующие данные)
- Только если confidence >= min_confidence (по умолчанию 0.7)
- Для внутренних доменов требуется сильный персональный сигнал (confidence >= 0.8)

### 3. Обработка граничных случаев

- **Несколько городов в подписи**: выбирается город с наивысшим приоритетом или по контексту роли
- **Города с дефисом**: корректно извлекаются (например, "Санкт-Петербург")
- **Внутренние сотрудники**: без персонального сигнала остаются с city=null, address=null
- **Защита от перезаписи**: существующие данные контакта не перезаписываются

### 4. Метаданные и отладка

Для каждого контакта сохраняются метаданные:
- `applied` - была ли применена локация
- `snippet` - фрагмент текста-источника
- `confidence` - уровень уверенности
- `source_type` - тип источника (signature, body_near_name, rejected_hq_block)
- `matched_patterns` - список совпавших паттернов
- `rejected_reason` - причина отклонения (если применимо)

### 5. Логирование

- **INFO**: применение локации с деталями
- **DEBUG**: отклонение локации, обнаружение HQ-блоков
- **ERROR**: ошибки обработки с продолжением работы
- Статистика после обработки: обработано, применено, отклонено, HQ-блоков обнаружено

## Критическое улучшение: Предотвращение HQ-backfill

**Проблема**: Даже после внедрения `contact_location_safety`, контакты без персональных сигналов получали HQ-адреса через метод `_backfill_contact_city_address`.

**Решение**: Модифицирована логика backfill в `postprocessor.py`:
- Backfill применяется **только** если у контакта уже есть `city` или `address` (т.е. был найден персональный сигнал)
- Если оба поля пустые - backfill **запрещен**, предотвращая HQ-протечки
- Это гарантирует, что контакты типа Клочковой-Абельянц (без email, без персональной локации) не получат HQ-адреса

**Результат**:
```
✅ Клочкова-Абельянц: city=null, address=null (без HQ-протечки)
✅ Воронова: city=Новосибирск (персональный сигнал сохранен)
```
