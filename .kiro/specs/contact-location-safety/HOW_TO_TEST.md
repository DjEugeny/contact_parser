# Как протестировать исправление TASK-008B

## ✅ Статус изменений

Все изменения применены корректно в коде:

```bash
$ python check_code_changes.py
✅ ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ!
```

## ⚠️ ВАЖНО: Перезапуск Python процесса

Изменения в коде **НЕ применятся автоматически**! Python кэширует импортированные модули в памяти.

### Необходимо:

1. **Остановить** все запущенные Python процессы обработки
2. **Перезапустить** процесс обработки писем
3. **Проверить** логи на наличие сообщений TASK-008B

## 🔍 Проверка работы

### 1. Проверка логов

После перезапуска в логах должны появиться сообщения:

```
🔍 TASK-008B: _apply_contact_location_safety вызван для X контактов
🔍 TASK-008B: _enrich_location_from_organization вызван для контакта ...
🔍 TASK-008B: _backfill_contact_city_address вызван для X контактов
🔒 Контакт ... без персональной локации. Обогащение HQ-локации пропущено
```

### 2. Проверка результатов

После обработки писем 016 и 017:

**Email 017 - Клочкова-Абельянц:**
```json
{
  "name": "Клочкова-Абельянц Сатеник Аршавиловна",
  "city": null,  // ✅ Должно быть null
  "address": null  // ✅ Должно быть null
}
```

**Email 017 - Воронова:**
```json
{
  "name": "Воронова Светлана Сергеевна",
  "city": "Новосибирск",  // ✅ Персональный сигнал
  "address": null  // ✅ Нет персонального адреса
}
```

## 🐛 Если проблема сохраняется

### Шаг 1: Проверить, что изменения в коде

```bash
python check_code_changes.py
```

Должно быть: `✅ ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ!`

### Шаг 2: Проверить логи

Искать в логах:
```bash
grep "TASK-008B" data/logs/*.log
```

Если логов нет - процесс не перезапустился!

### Шаг 3: Проверить конфигурацию

```bash
cat config/processing_config.json | grep -A 10 "contact_location_safety"
```

Должно быть:
```json
"contact_location_safety": {
  "enabled": true,
  ...
}
```

### Шаг 4: Принудительный перезапуск

1. Найти все Python процессы:
```bash
ps aux | grep python | grep contact_parser
```

2. Убить процессы:
```bash
kill -9 <PID>
```

3. Запустить заново
