# Анализ и исправление критического бага маппинга вложений

## 📋 Обзор проблемы

### Описание бага
В модуле `src/advanced_email_fetcher.py` обнаружена критическая проблема с маппингом вложений. Вложения из одного письма в треде некорректно приписываются другим письмам того же треда.

### Симптомы
- **Некорректное количество вложений**: В данных писем указано больше вложений, чем существует на диске
- **Дублирование вложений**: Одни и те же вложения приписываются разным письмам в треде
- **Нарушение бизнес-логики**: Неправильный анализ взаимодействий и коммерческих предложений

## 🎯 Корневая причина

### Проблема в архитектуре
Текущая система использует `thread_id` для определения принадлежности вложений:

```python
# ПРОБЛЕМНЫЙ КОД в оригинальном модуле
def save_attachment_or_inline(self, part, thread_id, date_folder, is_inline=False):
    # Вложения сохраняются с привязкой к thread_id
    filename = f"{thread_id}_{timestamp}_{prefix}_{safe_filename}"
```

### Почему это неправильно
1. **Thread_id объединяет письма**: Все письма в одной цепочке имеют одинаковый thread_id
2. **Вложения принадлежат конкретным письмам**: Каждое письмо имеет уникальный message_id
3. **Некорректное наследование**: Система приписывает все вложения треда каждому письму

## ✅ Решение: новая архитектура с message_id

### Ключевое изменение
Использовать `message_id` вместо `thread_id` для маппинга вложений:

```python
# ИСПРАВЛЕННЫЙ КОД в новой архитектуре
def save_attachment(self, part, message_id, thread_id, date_folder, is_inline=False):
    # Вложения сохраняются с привязкой к message_id
    filename = f"{message_id}_{timestamp}_{prefix}_{safe_filename}"
```

### Компоненты новой архитектуры

#### 1. AttachmentRegistry
```python
class AttachmentRegistry:
    def save_attachment(self, part, message_id, thread_id, date_folder, is_inline=False):
        # 🔄 КЛЮЧЕВОЕ: message_id вместо thread_id
        metadata = {
            "message_id": message_id,  # Точное соответствие письму
            "thread_id": thread_id,    # Для обратной совместимости
            "original_filename": original_filename,
            "saved_filename": saved_filename,
            # ... другие поля
        }
```

#### 2. EmailProcessor
```python
def _process_attachments(self, msg, msg_id, message_id, thread_id, date_folder):
    # 🔄 КЛЮЧЕВОЕ ИЗМЕНЕНИЕ: Используем message_id вместо thread_id
    attachment_info = attachment_registry.save_attachment(
        part=part,
        message_id=message_id,  # Используем message_id!
        thread_id=thread_id,    # Сохраняем thread_id для совместимости
        date_folder=date_folder,
        is_inline=is_inline
    )
```

#### 3. LegacyEmailFetcherV2
Обеспечивает обратную совместимость с существующим кодом.
