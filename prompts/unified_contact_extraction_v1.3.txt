## 🏢 ОРГАНИЗАЦИИ (organizations)
1. Собирай все найденные корпоративные email, телефоны, ИНН, сайты, город и адрес.
2. Включай контактные данные, не привязанные к конкретному человеку.
3. 📧 **КРИТИЧЕСКИ ВАЖНО для EMAILS:**
   - ✅ ВКЛЮЧАЙ в `organizations.emails` ТОЛЬКО:
     * Общие/ролевые ящики: `info@`, `sales@`, `support@`, `service@`, `office@`, `pr@`, `hr@`, `torgi@`, `mail@`, `hotline@`
     * Департаментные: `team@`, `marketing@`, `finance@`, `accounting@`, `buh@`
     * Технические: `noreply@`, `robot@`, `do-not-reply@`
     * Групповые алиасы: `*-all@`, `*-team@`, `*-group@`
   - ❌ НЕ ВКЛЮЧАЙ в `organizations.emails`:
     * Персональные адреса сотрудников с паттернами: `имя.фамилия@`, `и.фамилия@`, `фамилия@` (например: `m.gogoleva@dna-technology.ru`, `prisyazhnyuk@dna-technology.ru`, `s.voronova@dna-technology.ru`)
     * Даже если домен корпоративный (@dna-technology.ru), персональный адрес должен быть ТОЛЬКО в `contacts[].email`
4. Если email/телефон указан без ФИО — относись к organizations (например: "mail@org.ru", общий телефон).
5. Делай `organization_id` уникальным в пределах письма.
6. 🔍 ИНН: обязательно ищи числа из 10 или 12 цифр подряд (с префиксом «ИНН» или без него).
7. 🌐 Сайт: ищи домены/URL с точками (.ru, .com, .org и др.).
8. 📞 **Телефоны организации — формат объекта и правила:**
   - Возвращай телефоны массивом `phones[]`, каждый элемент — объект со СЛЕДУЮЩИМИ полями (ровно эти имена):
     - `type`: `"main" | "office" | "fax" | "mobile" | "other" | null` (если не уверен — `null`).
     - `number`: человекочитаемый номер **БЕЗ** добавочного (пример: `+7 (495) 640-17-71`).
     - `normalized`: формат **E.164** (например, `+74956401771`) или `null`, если не удалось валидировать.
     - `original`: исходная строка из письма/подписи (как есть).
     - `extension`: только цифры/DTMF добавочного (`0–9#*`) или `null`.
   - Если в номере встречается добавочный (`доб`, `доб.`, `доб:`, `ext`, `ext.`, `extension`, `x`), **не включай** его в `number`, а значение запиши в `extension`.
   - Конструкция вида `+7 (495) 933 71 47 (48)` — это **два номера**: `+7 (495) 933-71-47` и `+7 (495) 933-71-48`. Верни оба как два элемента `phones[]` с тем же `type`.
   - Не переносить телефоны между уровнями: HQ‑телефоны остаются в `organizations`, персональные — в `contacts`.
   - Не переносить телефоны из подписи другой организации. Если телефон фигурирует у контрагентов, оставляй его у той компании, к которой принадлежит домен e-mail / текст в подписи.
9. 📍 **ГОРОД И АДРЕС из вложений — КРИТИЧЕСКИ ВАЖНО:**
   - Текст вложений отделен от письма разделителем "=== ВЛОЖЕНИЕ N: [имя файла] ==="
   - При анализе текста после разделителя **определи организации-участники по контексту**:
     * **Отправитель документа** — организация с реквизитами (ИНН, адрес, банковские данные), блок "От:", "Поставщик:", "Исполнитель:"
     * **Получатель документа** — блок "Кому:", "Покупатель:", "Заказчик:", "для [город] Компания [название]"
     * **Конечный пользователь** — если указан отдельно (блок "Конечный пользователь:", "Конечный заказчик:")
   
   - **ПРАВИЛО ПРИНАДЛЕЖНОСТИ ГОРОДА И АДРЕСА:**
     * Город/адрес принадлежит организации ТОЛЬКО если находится в её контекстном блоке (в пределах 2-3 строк)
     * Город/адрес в блоке "Кому:" или "для [город] Компания" → ТОЛЬКО получатель
     * Город/адрес рядом с реквизитами (ИНН, банк) → ТОЛЬКО организация-владелец реквизитов
     * ❌ **НЕ присваивай** город/адрес одной организации → другим организациям из того же документа
     * ❌ **НЕ копируй** город/адрес между разными ролями (отправитель ≠ получатель)
     * ✅ **Город без адреса** - тоже важен! Если указан "для г. Москва, Компания МИЛЛАБ" → city="Москва" для МИЛЛАБ
   
   - **Признаки принадлежности города/адреса:**
     * Город/адрес находится в том же блоке, что и название организации
     * Город/адрес следует сразу после названия организации (в пределах 2-3 строк)
     * Город/адрес предваряется меткой "г.", "город", "Адрес:", "Юридический адрес:", "Местонахождение:"
     * Город/адрес в блоке "Кому:" или "для [город] Компания [название]" → получатель
     * Город/адрес в блоке "От:" или рядом с реквизитами отправителя → отправитель
   
   - **Признаки НЕпринадлежности города/адреса:**
     * Город/адрес находится в другом блоке документа (разные разделы)
     * Между организацией и городом/адресом есть другая организация
     * Город/адрес находится в тексте письма (до разделителя "=== ВЛОЖЕНИЕ"), а организация во вложении
     * Город/адрес относится к другой роли (например, адрес отправителя, а организация - получатель)
   
   - **Если не уверен** в принадлежности города/адреса → оставь `city: null, address: null`
   - **Лучше пропустить**, чем присвоить чужой город/адрес


## 👤 ПЕРСОНАЛЬНЫЕ КОНТАКТЫ (contacts)

🚨 **КРИТИЧЕСКИ ВАЖНО — ОБЯЗАТЕЛЬНОЕ ПРАВИЛО для включения контакта:**

1. **Контакт ДОЛЖЕН иметь хотя бы один способ связи:**
   - ✅ Email (корпоративный или личный)
   - ✅ Телефон (мобильный, рабочий, любой)

2. ❌ **НЕ ВКЛЮЧАЙ в contacts[]:**
   - Контакты только с ФИО без email И без телефона
   - Подписи из документов (КП, договоры, акты) без контактных данных
   - Лица из поля CC/BCC, если у них нет email
   - Упоминания ЛПР без способов связи
   - Директора/подписанты документов без email/телефона
   - Имена из текста письма без явных контактных данных

3. ✅ **Минимум для включения**: ФИО + (email ИЛИ телефон)

4. **Примеры:**
   - ✅ "Иванов Иван, i.ivanov@company.ru" → ВКЛЮЧАЙ
   - ✅ "Петрова А.С., +7 (916) 123-45-67" → ВКЛЮЧАЙ
   - ❌ "Директор Сидоров С.С." (без контактов) → НЕ ВКЛЮЧАЙ
   - ❌ "Подпись: Козлов А.А." (без контактов) → НЕ ВКЛЮЧАЙ
   - ❌ "Менеджер Смирнова" (без контактов) → НЕ ВКЛЮЧАЙ

5. **ВАЖНО для organization_id:**
   - Если контакт связан с организацией → указывай `organization_id` (1, 2, 3...)
   - Если письмо личное (друзья, родственники, нет компаний) → `organization_id: null`
   - В большинстве деловых писем контакты ДОЛЖНЫ иметь organization_id

6. Указывай `role_in_message` (например: `"sender"`, `"recipient"`, `"cc"`, `"requested_quote"`, `"sent_quote"`, `"complaint"`, `"follow_up"`, `"info_request"`).  

7. 📞 **Телефоны — формат объекта и правила:**
   - Возвращай телефоны массивом `phones[]`, каждый элемент — объект со СЛЕДУЮЩИМИ полями (ровно эти имена):
     - `type`: `"main" | "mobile" | "office" | "fax" | "other" | null` (если не уверен — `null`).
     - `number`: человекочитаемый номер **БЕЗ** добавочного (пример: `+7 (495) 640-17-71`).
     - `normalized`: формат **E.164** (например, `+74956401771`) или `null`, если не удалось валидировать.
     - `original`: исходная строка из письма/подписи (как есть).
     - `extension`: только цифры/DTMF добавочного (`0–9#*`) или `null`.
   - Если в номере встречается добавочный (`доб`, `доб.`, `доб:`, `ext`, `ext.`, `extension`, `x`), **не включай** его в `number`, а значение запиши в `extension`.
   - Конструкция вида `+7 (495) 933 71 47 (48)` — это **два номера**: `+7 (495) 933-71-47` и `+7 (495) 933-71-48`. Верни оба как два элемента `phones[]` с тем же `type`.
   
   **ВАЖНО для телефонов из вложений (КП, договоры, счета, акты, счёт-фактуры, другие вложения, где есть контактные данные):**
   - Если телефон указан **рядом с именем конкретного лица** (в пределах 2-3 строк), присваивай его **КОНТАКТУ**, а не организации
   - Примеры контекста для присвоения телефона контакту:
     * "Пашову Виктору\nТел.: +7 (905) 088 88 82" → телефон контакта Пашов Виктор
     * "Контактное лицо: Иванов Иван\nМоб.: +7 900 123-45-67" → телефон контакта Иванов Иван
     * "Менеджер Петрова А.С.\n+7 (495) 123-45-67" → телефон контакта Петрова А.С.
   - Если телефон в **общем блоке организации** (шапка документа, реквизиты, подпись компании) → телефон организации
   - Если сомневаешься в принадлежности телефона → присваивай организации (безопаснее)

8. Город и адрес для персонального контакта:
   - НЕ КОПИРУЙ адрес из организации. Если в тексте письма нет ЯВНОЙ привязки адреса к этому человеку (его собственная подпись или строка рядом с его ФИО), у контакта "address" = null.
   - Город тоже НЕ КОПИРУЙ из организации. Укажи "city" ТОЛЬКО если он явно содержится в подписи/строке контакта ИЛИ в явном описании этого человека (например: "Региональный представитель в СФО, г. Новосибирск").
   - Служебные/корпоративные подписи (адрес HQ, адрес офиса из общего блока компании) НЕ считаются персональным адресом контакта. Не наследуй их в контакт.
   - Если не уверен, оставь "city": null и "address": null.

9. 🚨 **ПОВТОРЯЮ: Не включай контакты без способов связи!**
   - Контакт БЕЗ email И БЕЗ телефона = НЕ ВКЛЮЧАЙ в contacts[]
   - Такие упоминания (ФИО без контактов) можно отметить в business_context или key_points, но НЕ в массиве contacts[]

⚠️ ПРАВИЛО ДЛЯ ТЕЛЕФОНОВ: Не переносить телефоны из подписи другой организации. Если телефон фигурирует у контрагентов, оставляй его у той компании, к которой принадлежит домен e-mail / текст в подписи. Чётко указать, что HQ-реквизиты не следует копировать в другие организации, кроме той, что указана в подписи.

## 💼 КОММЕРЧЕСКИЕ ПРЕДЛОЖЕНИЯ (commercial_offers)
Включай только реальные КП (явные признаки: номер/дата/условия/сумма/valid_until).  
- 📎 Заполняй `commercial_offers` **только** если в тексте письма или OCR-вложений есть явное коммерческое предложение: фраза «коммерческое предложение»/«КП» **и** позиции с ценами (`unit_price`, `total_price`).  
- ✉️ Если вложений с КП нет (письмо содержит лишь просьбу подготовить КП или обсуждение), возвращай `"commercial_offers": []`.

Структура элемента:  
- `found`: true/false  
- `offer_type`: «Приборы», «Наборы» или «Другое»  
- `offer_number`: номер КП или "б/н"  
- `offer_date`: дата выдачи (ISO 8601) или null  
- `end_user`: конечный пользователь  
- `end_user_inn`: ИНН конечного пользователя  
- `intermediary`: кому выдано КП (контакт или организация)  
- `intermediary_date`: контактные данные получателя (город, компания, должность, телефон, email)  
- `payment_terms`: условия оплаты  
- `delivery_time`: срок поставки  
- `delivery_terms`: условия доставки  
- `valid_until`: дата окончания действия (ISO 8601)  
- `equipment_items`: список позиций оборудования/наборов  
- `total_cost`: общая стоимость (число)  
- `comments`: важные дополнительные сведения

Каждый элемент `equipment_items` должен включать: `name`, `model`, `article`, `quantity`, `unit_price`, `total_price`, `vat`.

💡 Если не уверен, что это КП — верни `commercial_offers: []`.

## 🔁 ВЗАИМОДЕЙСТВИЯ (interactions)
- Создай записи для ключевых контактов/организаций.  
- Указывай `role_in_message`, `interaction_type`, краткое `summary`, ссылки на вложения.  
- Заполняй `message_subject`, `message_date` (ISO 8601) и `message_id_hint`, если данные доступны.

### Словарь `interaction_type`
- `requested_quote`  
- `sent_quote`  
- `follow_up`  
- `clarification`  
- `complaint`  
- `invoice_sent`  
- `invoice_paid`  
- `contract_sent`  
- `contract_signed`  
- `delivery`  
- `support`  
- `other`

### ✅ ДОПОЛНЕНИЕ ДЛЯ MVP: «человеческая» заметка и участники
Для **каждого** элемента `interactions[]` дополнительно верни:  
- `human_note` — 1–2 короткие фразы на живом русском языке, без канцелярита, акцент на людях:  
  - кто инициирует (ФИО + организация), кому адресует (ФИО/отдел),  
  - что конкретно просит/сообщает (действие + объект),  
  - отсылка к ключевому артефакту (КП №, счёт №, мероприятие, дата), если есть.  
  Примеры начала: «Ольга Козлова (ДНК-Технология) уточняет…», «Елена Хаменкова (МЕД КОНГРЕСС) прислала…».
- `participants`:  
  {
    "actor": "Фамилия Имя (Организация, должность)",
    "audience": ["Фамилия Имя (Организация)", "..."]
  }

## 🚫 ПРИМЕРЫ НЕПРАВИЛЬНОГО JSON (НЕ ДЕЛАЙ ТАК!)

### ❌ Ошибка 1: null в обязательных полях
```json
{
  "contacts": [
    {
      "contact_id": null,  // ❌ НЕПРАВИЛЬНО! Должно быть число

    }
  ]
}
```

```json
{
  "interactions": [
    {
      "interaction_type": "info_request"  // ❌ НЕПРАВИЛЬНО! Используй "clarification"
    }
  ]
}
```

### ❌ Ошибка 3: Отсутствие обязательных связей
```json
{
  "organizations": [
    {"organization_id": 1, "name": "Компания А"}
  ],
  "contacts": [
```
