## **ЭТАП 3. Доработка алгоритма постобработки (ETL/CRM-логика)**

**3.1. Дедупликация и слияние организаций:**

- Сопоставление организаций по названиям, ИНН, сайтам (strict/fuzzy).
- Пример:
    - Если в одном письме `organization_id: 1`, а в базе уже есть такая организация с глобальным organization_id: 100, то объединить данные.
- Накапливать все emails, phones, адреса, выявлять уникальные значения.

**3.2. Генерация глобальных идентификаторов:**

- Все локальные organization_id и contact_id, выданные LLM, пересчитать в глобальные после объединения (валидация связей).

**3.3. Обновление связей для персональных контактов:**

- Перевод локального organization_id каждого контакта в глобальный — сохранять связь контакта с организацией.

**3.4. Фильтрация и “ценность” контактов:**

- Реализовать функцию evaluate_contact_value как в мини-ТЗ:

```python
def evaluate_contact_value(contact):
    score = 0
    if contact.get('name'): score += 3
    if contact.get('organization'): score += 2
    if contact.get('position'): score += 2
    if contact.get('email'): score += 2
    if contact.get('phones'): score += 2
    if contact.get('city'): score += 1
    if contact.get('inn'): score += 1
    return score >= 4
```

- Включать в итоговую базу только контакты, которые “ценны” по этому критерию.

**3.5. Обработка "пустых" (без имени и должности) контактов:**

- Все email и phones без ФИО и позиции — будут сохраняться только как assets организации (organizations.emails, organizations.phones).
- Исключать их из contacts.

**3.6. Обогащение данных о городах и адресах:**

- Если для контакта нет адреса — брать из организации.
- Если есть отдельный адрес/город у контакта — сохранять его индивидуально.

**3.7. Нормализация данных:**

- Телефоны — очистка формата, приведение к единому виду, типизация.
- Email — валидация по строке.
- Категоризация — при необходимости раскидывать контакты по “важности”, если функционал потребуется.
