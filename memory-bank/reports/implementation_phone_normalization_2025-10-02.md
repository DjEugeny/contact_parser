# 📊 Implementation: Phone Extension Normalization (PLAN-005)

## 🎯 Цель
Реализовать корректную нормализацию телефонов с добавочными номерами согласно PLAN-005. Исправить критическую проблему с дубликатами телефонов в email_014 и email_015, где строка `+7 (495) 933 71 47 (48), доб.171` создавала дубликаты вместо двух отдельных номеров.

## 🔧 Выполненная работа

### 1. Анализ проблемы ✅
- Выявлена корневая причина: PhoneNormalizer неправильно парсил `(48)` как второй номер
- Создан PLAN-005_Phone_Extension_Normalization.md с детальной спецификацией
- Определены требования и архитектурные изменения

### 2. Обновление JSON Schema ✅
- **Файл**: `src/core/validator.py`
- Изменена схема `organizations.phones` и `contacts.phones`
- Добавлена поддержка объектов phones с полями `{type, number, normalized, original, extension}`
- Добавлена backward compatibility для строковых телефонов
- Убрана `uniqueItems: true` (дедупликация в PostProcessor)

### 3. Исправление PhoneNormalizer ✅
- **Файл**: `src/postprocessing/phone_normalizer.py`
- Добавлен метод `normalize_phone_to_object()` - главная функция нормализации
- Добавлен метод `_extract_extension_new()` - улучшенное извлечение добавочных
- Добавлен метод `_split_compound_phones()` - распознавание множественных номеров типа `(48)`
- Добавлен метод `_normalize_to_e164()` - нормализация в E.164 без добавочного
- **УДАЛЕН** код добавления extension обратно в `formatted` в `normalize_contact_phone()`
- Поддержка всех форматов добавочных: `доб.`, `ext`, `x`, `вн.` и т.д.

### 4. Обновление LLM Prompt ✅
- **Файл**: `prompts/unified_contact_extraction_structured.txt`
- Добавлены инструкции по обработке телефонов без добавочных в поле `number`
- Инструкции по парсингу множественных номеров `(48)`
- Примеры правильных и неправильных форматов телефонов

### 5. Интеграция в PostProcessor ✅
- **Файл**: `src/postprocessing/postprocessor.py`
- Добавлен метод `_normalize_all_phones()` - нормализация всех телефонов в пайплайне
- Добавлен метод `_deduplicate_phones()` - дедупликация по `(normalized, extension, type)`
- Интеграция в `process_llm_response()` после `_cleanup_organization_emails`
- Сбор статистики в `postprocessing_metadata.phone_normalization`

### 6. Написание тестов ✅
- **Unit-тесты**: `tests/test_phone_normalization.py`
  - Тест парсинга добавочных номеров
  - Тест множественных номеров с добавочным
  - Тест E.164 нормализации
  - Тест дедупликации
- **Интеграционные тесты**: `tests/integration/test_email_014_015.py`
  - Тест обработки email_014 и email_015
  - Проверка структуры phones (объекты, extension отдельно)
  - Проверка отсутствия дубликатов
