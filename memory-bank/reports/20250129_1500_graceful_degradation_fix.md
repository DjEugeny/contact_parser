# Исправление Graceful Degradation в Валидаторе

## Проблема
Тест `test_graceful_degradation` падал с ошибкой - валидатор возвращал `is_valid=True` вместо ожидаемого `False` для полностью невалидных данных.

## Анализ
1. **Корневая причина**: В методе `_auto_correct_response` отсутствовала проверка на полную невалидность структуры данных
2. **Проблема с тестами**: Тесты использовали mock класс вместо настоящего валидатора из-за проблем с относительными импортами

## Выполненные исправления

### 1. Создание специального исключения
- Добавлен класс `InvalidStructureError` в `validator.py`
- Отделяет полную невалидность структуры от других ошибок валидации

### 2. Улучшение логики автокоррекции
- В методе `_auto_correct_response` добавлена проверка наличия хотя бы одного валидного поля
- При полном отсутствии валидных полей выбрасывается `InvalidStructureError`

### 3. Обработка нового исключения
- В методе `validate_llm_response` добавлена отдельная обработка `InvalidStructureError`
- Корректно возвращает `is_valid=False` и fallback-ответ

### 4. Исправление импортов в тестах
- Изменен импорт в `test_new_validator.py` для использования настоящего валидатора
- Обход проблемы с относительными импортами через прямой импорт из файла

## Результат
- ✅ Все 6 тестов валидатора проходят успешно
- ✅ Graceful degradation работает корректно
- ✅ Полностью невалидные данные корректно обрабатываются с возвратом `is_valid=False`
- ✅ Fallback-структура создается правильно

## Измененные файлы
- `src/core/validator.py` - добавлено исключение и улучшена логика
- `tests/test_new_validator.py` - исправлен импорт валидатора
