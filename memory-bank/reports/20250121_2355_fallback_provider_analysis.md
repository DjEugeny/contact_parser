## Обнаруженные проблемы

### 1. Логика переключения провайдеров
**Файл:** `src/llm_extractor.py`, метод `_make_llm_request_with_retries` (строки 583-714)

**Проблема:** Система переключается на следующий провайдер при любой ошибке, даже если текущий провайдер работает нормально, но произошла временная ошибка (например, JSON parsing error).

**Код проблемы:**
```python
# Пробуем переключиться на другого провайдера
if self._switch_to_next_provider():
    print(f"🔄 Повторяем запрос с новым провайдером")
    continue  # Повторяем попытку с новым провайдером
```

**Последствия:**
- Ненужные переключения провайдеров при временных ошибках
- Потеря приоритетного провайдера из-за случайных ошибок
- Увеличение статистики fallback без реальной необходимости

### 2. Circuit Breaker работает некорректно
**Файл:** `src/llm_extractor.py`, метод `_is_provider_in_circuit_break` (строки 1756-1790)

**Проблема:** Circuit Breaker проверяется только перед переключением, но не учитывается при инициализации провайдера.

**Код проблемы:**
```python
# Проверяем Circuit Breaker перед переключением
if self._is_provider_in_circuit_break():
    print(f"🔌 Circuit Breaker: провайдер {self.providers[self.current_provider]['name']} отключен")
    # Пробуем переключиться на другого провайдера
    if self._switch_to_next_provider():
        print(f"🔄 Повторяем запрос с новым провайдером")
        continue
```

**Последствия:**
- Провайдер может быть в circuit break, но система продолжает его использовать
- Неэффективное использование ресурсов на заведомо неработающих провайдерах

### 3. Отсутствие учета failure_count при ошибках
**Файл:** `src/llm_extractor.py`, метод `_make_llm_request_with_retries`

**Проблема:** При ошибках не увеличивается счетчик `failure_count` для текущего провайдера, что делает Circuit Breaker неэффективным.

**Отсутствующий код:**
```python
# Должно быть добавлено при обработке ошибок:
self.providers[self.current_provider]['failure_count'] += 1
self.providers[self.current_provider]['last_failure'] = datetime.now().isoformat()
```

### 4. Неправильная обработка rate limit ошибок
**Файл:** `src/llm_extractor.py`, строки 650-670

**Проблема:** При rate limit ошибках система ждет и повторяет запрос к тому же провайдеру, вместо переключения на другой.

**Код проблемы:**
```python
if "Rate limit (HTTP 429)" in error_msg:
    # Exponential backoff вместо переключения провайдера
    actual_wait = min(exponential_wait, max_wait)
    time.sleep(actual_wait)
    continue
```

**Последствия:**
- Долгие ожидания вместо быстрого переключения
- Неэффективное использование доступных провайдеров

## Объяснение поведения "ошибки доступа, но следующие письма обрабатываются успешно"

**Причина:** Система переключается на другой провайдер при первой же ошибке, даже если она временная. Следующие письма обрабатываются успешно, потому что:

1. **Переключение провайдера:** После ошибки система переходит на Groq или другой провайдер
2. **Временные ошибки:** Первоначальная ошибка могла быть временной (network timeout, temporary rate limit)
3. **Разные провайдеры:** Новый провайдер может иметь другие лимиты и ограничения

**Пример сценария:**
1. OpenRouter возвращает временную ошибку (например, timeout)
2. Система переключается на Groq
3. Groq успешно обрабатывает следующие письма
4. OpenRouter мог бы снова работать, но система уже переключилась
