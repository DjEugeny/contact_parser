## 🎯 Описание проблемы

### Контекст
При обработке файлов OCR процессором возникла критическая проблема дублирования обработки одних и тех же файлов. Особенно остро проблема проявлялась на определенных датах, где система создавала несколько копий результатов для одних и тех же исходных файлов.

### Корень проблемы
OCR процессор не распознавал файлы с **одинаковыми именами, но разными временными метками** как один и тот же файл. Это происходило из-за того, что:

1. Файлы в именах содержали временные метки: `_033xxx_` (новые) vs `_07xxxx_` (старые)
2. Система проверяла точное совпадение имен файлов, включая временные метки
3. Один и тот же файл обрабатывался несколько раз с разными временными метками

### Примеры проблемных файлов

#### Папка 2025-07-21:
```
Исходные файлы: одинаковые имена, разные метки времени
20250721_mail_ru_3e6a56b8_033842_attach_IMG-20250721-WA0003.txt  ← НОВЫЙ
20250721_mail_ru_3e6a56b8_083944_attach_IMG-20250721-WA0003.txt  ← СТАРЫЙ (дубликат)

Результат: 2 файла результата вместо 1
```

#### Папка 2025-07-14:
```
20250714_dna-technology_ru_a82f46c2_033733_attach_Счет на оплату _ 8067 от 14.07.2025.txt  ← НОВЫЙ
20250714_dna-technology_ru_a82f46c2_081406_attach_Счет на оплату _ 8067 от 14.07.2025.txt  ← СТАРЫЙ (дубликат)
```

### 2. Создание скрипта для удаления существующих дубликатов

**Файл:** `remove_duplicates.py`

#### Функционал скрипта:
- **Анализ:** Сканирует папки на наличие дублированных файлов
- **Парсер:** Корректно разбирает имена файлов по компонентам
- **Группировка:** Группирует дубликаты по оригинальным именам файлов

- **Безопасность:** Работает в двух режимах (анализ/удаление)

#### Алгоритм работы:
```python
1. Парсим имя файла → извлекаем оригинальное имя
2. Группируем файлы по ключу: {дата}_{домен}_{оригинальное_имя}
3. Для каждой группы дубликатов:
   - Сортируем по времени модификации (новые сначала)
   - Оставляем первый (самый новый)
   - Удаляем остальные
```
