# Извлечение, валидация, дедупликация

## 1) Консолидация входных данных
- Собрать `combined_text = email.body_text + '\n\n' + sum(attachment_texts)`.
- Сформировать промпт (см. `09_PROMPTS_AND_VALIDATION.md`) и отправить в LLM.
- Получить **строгий JSON** → проверить по JSON Schema → иначе повторить с инструкцией об ошибке.

## 2) Нормализация
- Телефоны → E.164 (RU: +7XXXXXXXXXX), выделять добавочные `xNNN`.
- Email → lowercase, trim, валидация RFC, домен.
- ИНН → цифры, длина 10/12, контрольное число (опционально).
- Город → нормализованный справочник (Новосибирск и пр.).

## 3) Дедупликация (детерминированная)
- Контакт: по email **или** (телефон + ФИО нормализованное).
- Организация: по ИНН **или** (название + сайт/домен).

## 4) Мягкий фуззи‑мэтч
- Алгоритм: комбинированный скоринг (Jaro-Winkler ФИО, Levenshtein названия, домен совпадает = +w, город совпадает = +w).
- Порог: `score < 0.75` → в `moderation_queue`.
- При объединении хранить `confidence` и ссылку на источник (email_id).

## 5) История взаимодействий
- По роли контакта в письме: определить `role` из заголовков (From/To/CC) + LLM‑классификация намерения: запрос КП, отправка КП, уточнение, рекламация и др.
- Создавать `Interaction` на каждый релевантный контакт/организацию, связывать с `email_id`.

## 6) Модерация
- Экран «Модерация»: список с группировкой по типу сущности, полями, confidence, быстрыми действиями «Объединить/Создать/Игнорировать».
