# STEP_BY_STEP_PLAN — Шаги реализации (синхронизировано)

## Шаг 0. Подготовка окружения
- Проверить .env и доступы IMAP/LLM/Vision/Supabase.  
- Создать проект в Supabase (бесплатный тариф).
- Применить миграции схемы БД в Supabase.
- Настроить подключение через supabase-py или psycopg2.

## Шаг 1. Тестовый раннер (api_pipeline_validator.py)
- Подключить существующие fetcher+OCR.  
- Встроить LLM‑вызов с **обновлённым промптом**.  
- Реализовать валидатор/нормализацию/дедуп/обогащение.  
- Писать в PostgreSQL (Supabase) + отчёт Inbox.

## Шаг 2. Миграция существующих данных
- Создать скрипт `migrate_llm_results_to_supabase.py`.
- Обработать все JSON файлы из `data/llm_results/`.
- Применить валидацию и дедупликацию.
- Загрузить в PostgreSQL через Supabase API.

## Шаг 3. Backend + Frontend (MVP)
- FastAPI + React (PWA): search, карточки, реестр КП, уведомления.  
- Модерационный inbox в UI.

## Шаг 4. Автоматизация и размещение
- Выбрать вариант автоматического запуска (см. [17_DEPLOYMENT_OPTIONS.md](17_DEPLOYMENT_OPTIONS.md)):
  - Локально: cron/launchd на macOS
  - Облачно: Railway, Render, Fly.io, AWS Lambda + EventBridge
- Настроить ежедневный запуск конвейера.
- Бэкапы PostgreSQL (встроенные в Supabase) и каталога данных.
