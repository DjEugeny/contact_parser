# 09_PROMPTS_AND_VALIDATION — Промпты, валидация и постобработка (v3)

## 0) Назначение
Единый промпт для извлечения **организаций**, **контактов**, **коммерческих предложений (КП)** и **истории взаимодействий (interactions[])** из текста письма и всех его вложений.
Язык анализа — **русский**, английские участки игнорировать.

## 1) Канонический промпт (RU)
🎯 ЗАДАЧА:
- Проанализируй текст письма и всех вложений ниже (объединённый текст).
- 🚨 КРИТИЧЕСКИ ВАЖНО: Отвечай ТОЛЬКО валидным JSON без каких-либо дополнительных тегов, комментариев или объяснений!
- Не придумывай данные. Заполняй только то, что следует из текста.
- `organization_id` и `contact_id` — **локальные** ID в пределах одного письма, начиная с 1. Для ссылок между блоками используй эти локальные ID.
- Обязательно заполни блок **interactions[]** — краткие событие(я) взаимодействия из письма (см. словарь типов ниже).
- Заполняй `confidence` в [0,1] по каждому контакту и interaction.

📋 ПРАВИЛА ИЗВЛЕЧЕНИЯ:

## 🏢 ОРГАНИЗАЦИИ (organizations):
1. Собирай все найденные корпоративные email, телефоны, ИНН, сайты, город и адрес
2. Включай контактные данные БЕЗ привязки к конкретному человеку
3. Если email/телефон указан без ФИО — относи к organizations (например: "mail@org.ru", общий телефон)
4. organization_id делай уникальным для каждой организации
5. 🔍 ИНН: ОБЯЗАТЕЛЬНО ищи числа из 10 или 12 цифр подряд
6. 🌐 САЙТ: ОБЯЗАТЕЛЬНО ищи слова с точками (.ru, .com, .org)
7. Накапливай ВСЕ способы связи организации в массивы emails и phones

## 👤 ПЕРСОНАЛЬНЫЕ КОНТАКТЫ (contacts):
1. Добавляй ТОЛЬКО **ценные** (валидные) контакты с достаточной информацией
2. Минимум: ФИО (или хотя бы инициалы/фамилию), плюс хотя бы один способ связи (email или телефон)
3. Каждый контакт ОБЯЗАТЕЛЬНО должен иметь organization_id
4. Для каждого **контакта** укажи `role_in_message` (например: "sender", "recipient", "cc", "requested_quote", "sent_quote", "complaint", "follow_up", "info_request").
5. Сохраняй телефоны ТОЧНО как в тексте в массиве phones
6. Если у контакта несколько телефонов (мобильный, рабочий, факс) — сохраняй все в массив
7. Указывай тип телефона: "main", "mobile", "office", "fax" или null
8. 📍 ОБЯЗАТЕЛЬНО заполняй поля "address" и "city":
   - Если есть в явном виде — сохраняй как есть
   - Если для контакта не указан — копируй из связанной организации
9. НЕ включай контакты без имени (ФИО или инициалы) И без способов связи (например, только “ООО Ромашка” или "info@romashka.ru" — такие идут в organizations)

## 💼 АНАЛИЗ КОММЕРЧЕСКИХ ПРЕДЛОЖЕНИЙ

⚠️ КРИТИЧЕСКИ ВАЖНО: Возвращай коммерческое предложение в массив "commercial_offers" ТОЛЬКО если:

✅ **ВКЛЮЧАТЬ В commercial_offers:**
- В письме/вложении явно присутствует оригинал или копия коммерческого предложения от ООО "ДНК-Технология"
- Есть заголовок "Коммерческое предложение", "КП" или аналогичный
- Четко заполнены: итоговая стоимость (total_cost), дата/номер КП, условия оплаты/поставки
- Документ содержит: кому выставлено (клиент/партнер), что, когда и на каких условиях
- Перечень оборудования, реагентов с ценами

❌ **НЕ ВКЛЮЧАТЬ в commercial_offers:**
- Анкеты, заявки на участие в акции, документы "на ознакомление"
- Внутренние запросы, обсуждения, переписку по поводу КП без самого документа
- Закрывающие документы (счета-фактуры, акты) без коммерческого предложения
- Архивные факты старых КП, когда в письме содержится только ссылка/фраза "раньше выставляли КП", но самого нового документа нет
- Обсуждения типа "просим выставить", "мы выслали" без приложенного КП

💡 **Если сомневаешься** - лучше НЕ включай в commercial_offers (верни [])

**СТРУКТУРА КОММЕРЧЕСКОГО ПРЕДЛОЖЕНИЯ:**
- found: true/false (найдено ли КП)
- offer_type: Тип КП (Приборы/Наборы)
- offer_number: Номер КП или "б/н" если не указан
- offer_date: Дата выдачи КП (если указана)
- end_user: Конечный пользователь/организация
- end_user_inn: ИНН конечного пользователя
- intermediary: Кому выдано КП (контактное лицо)
- intermediary_date: Контактные данные кому выдано КП (город, фирма, должность, если есть, телефон, e-mail)
- payment_terms: Условия оплаты (предоплата, рассрочка)
- delivery_time: Срок поставки
- delivery_terms: Условия доставки (самовывоз, транспорт)
- valid_until: Срок действия предложения
- equipment_items: Детальная информация об оборудовании
- total_cost: Общая стоимость
- comments: Дополнительная важная информация

**ФОРМАТ ОБОРУДОВАНИЯ:**
Каждый элемент должен содержать:
- name: Название оборудования, реагентов (Амплификатор, Анализатор, Набор реагентов)
- model: Модель прибора, набора  (ДТ-96, ДТпрайм, ДТлайт, Фемофлон II, Бакрезиста)
- article: Артикул/код товара
- quantity: Количество единиц
- unit_price: Цена за единицу (число)
- total_price: Общая цена позиции (число)
- vat: НДС в процентах ("20%", "без НДС")

## 3) Словарь interaction_type
- `requested_quote` — контакт запросил КП;
- `sent_quote` — контакт отправил КП;
- `follow_up` — напоминание/дожим по открытым вопросам;
- `clarification` — уточнение параметров;
- `complaint` — рекламация/претензия;
- `invoice_sent`, `invoice_paid` — счёт отправлен/оплачен;
- `contract_sent`, `contract_signed` — договор отправлен/подписан;
- `delivery`, `support`, `other` — прочие.

## 4) Валидация и ретрай
- Проверка шаблона (Pydantic/`jsonschema`). При ошибке — ретрай с объяснением, какой ключ/тип ожидается.
- Нормализация: телефоны (E.164 RU), даты (ISO‑8601), суммы (числа), email → lower, ИНН (проверка длины/цифр).

## 5) Постобработка
- Дедуп/маппинг локальных `organization_id` → глобальные (см. `11_DEDUP_ENRICH_RULES.md`).  
- Замена ссылок в `contacts[]`/`interactions[]` на глобальные ID при записи в БД.  
- Фильтр «ценности» контактов (score ≥ 4) и отправка сомнительных — в Inbox.
