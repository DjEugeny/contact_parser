# 11_DEDUP_ENRICH_RULES — Дедупликация, маппинг ID и обогащение

## A) Организации: локальные → глобальные
1. Берём organizations[] из ответа LLM (локальные `organization_id: 1..N`).  
2. Ищем совпадение по базе: **строгое** (ИНН/домен) → **fuzzy** (название, адрес).  
3. Найдена? — используем **существующий глобальный id**, аккуратно **мёрджим** emails/phones/address.  
4. Не найдена? — создаём **новую** организацию (AUTO_INCREMENT id).  
5. Строим **маппинг** `{local_org_id: global_org_id}` для текущего письма.

## B) Контакты: обновление ссылок
- Для каждого контакта в contacts[] заменяем локальный `organization_id` на глобальный по маппингу из A).

## C) Контакты: scoring и фильтрация
```
score = name(3) + organization(2) + position(2) + email(2) + phones(2) + city(1) + inn(1)
включать если score ≥ 4
```

## D) Нормализация и обогащение
- Телефоны → единый формат + типы; email → lower; перенос city/address из организации, если в контакте пусто.  
- При наличии корпоративного домена email — выставить сайт организации при его отсутствии (консервативно).  
- ИНН — проверка контрольной суммы; при невалидности — флаг и в Inbox.

## E) История взаимодействий
- На каждый контакт/организацию в письме — запись в `interactions` с `role_in_message` и ссылками на исходники.  
- Роли: `sender`, `recipient`, `cc`, `requested_quote`, `sent_quote`, `follow_up`, `complaint`, `info_request` и т.п. (набор можно расширять).
