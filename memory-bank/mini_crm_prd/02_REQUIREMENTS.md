# 02_REQUIREMENTS — Детальные требования (обновлено)

**Статус:** Draft v2

## 1) Источники и форматы
- **IMAP (STARTTLS:143 / SMTP STARTTLS:587)** — корпоративный сервер `mail.dna-technology.ru`.
- Хранить:  
  a) **JSON письма** (как сейчас) — тело, заголовки, метаданные, список вложений (пути);  
  b) **(Рекомендуется) .eml** — сырое письмо RFC822, чтобы открывать в системном клиенте (кроссплатформенно);  
  c) `message_id` — для ссылочной связи внутри БД/интерфейса.
- Вложения: PDF/DOCX/XLSX/изображения (часто PDF). OCR обязателен для сканов.

## 2) Переход из карточки к исходному письму
- **Открыть письмо** — основное действие: открыть `.eml` если сохранён, иначе встроенный просмотрщик по JSON (текст + список вложений).
- **Дополнительно (админ-меню «⋯»):** скачать `.eml` (если есть), скачать JSON письма (для отладки), «скопировать тему и отправителя».
- **Message‑ID:** хранить и показывать, но **не** полагаться на универсальные URL-схемы (`message://`, `outlook:`) — ненадёжно.
- Если `.eml` пока не сохраняется — используем встроенный просмотрщик и копирование темы/отправителя. В fetcher запланировать опцию сохранения RFC822 (низкий приоритет).

## 3) Извлечение и структура данных (LLM)
- Единый промпт **unified_contact_extraction_structured** с блоками: `organizations[]`, `contacts[]`, `commercial_offers[]`, `business_context`, `summary`, `key_points` и **role_in_message** для каждого контакта.  
- Контакты — только «ценные» (порог score, см. постобработку).  
- Организации — аккумулируют корпоративные e‑mail/телефоны/адреса/ИНН.  
- КП — включать только реально выставленные КП (наличие номера/даты/итога и явных атрибутов).

## 4) Постобработка
- **Валидация JSON** (Pydantic) → **Нормализация** (телефоны, email, адреса) → **Дедуп** (fuzzy: название/ИНН/домен; маппинг локальных org_id → глобальные) → **Обогащение** (ИНН‑чек, домен→сайт).  
- Все сомнительные сущности — в **модерационный inbox** (UI + лист в Google Sheets).

## 5) Поиск и интерфейс
- Поля поиска «день 1»: ФИО, телефон, город, организация, ИНН, email; мультикритериальные фильтры; сортировка (в т.ч. по алфавиту).
- Карточки: **Организация** — реквизиты, контакты, общая лента, все КП; **Контакт** — основные поля, лента взаимодействий, связанные КП.  
- Реестр КП — таблица (сортировка по организации/дате/сроку/статусу).  
- Dashboard — быстрый поиск + «новые/обновлённые контакты/организации» + «КП со сроком, который истекает».
- PWA (RU‑интерфейс), без тёмной темы/горячих клавиш.

## 6) Напоминания
- По `valid_until` в КП: уведомления за N дней до истечения (настройка).  
- В MVP — внутри веб‑приложения; позже — системные/мобильные push.

## 7) Нефункциональные
- Хранилище **SQLite** (локальный файл `crm.db`), переход на Postgres — миграцией.  
- Минимум внешних сервисов; поставить CRON для ежедневного запуска.  
- Бэкапы — по расписанию (копия `crm.db` и каталога данных).
