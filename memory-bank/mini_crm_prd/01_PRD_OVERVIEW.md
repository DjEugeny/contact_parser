# 01_PRD_OVERVIEW — Общее описание и цели проекта

**Проект:** Mini-CRM (однопользовательская версия)  
**Дата:** 2025‑09‑27  
**Статус:** Draft v2 (с учётом правок по комментариям)

## 1. Краткое описание
Mini‑CRM — это локально управляемая CRM‑система для одного пользователя (жены — регионального представителя) с последующим возможным переносом на VPS. Источник данных — архив корпоративной почты за 5+ лет (~19 000 писем), включая вложения. Система извлекает организации, персональные контакты и коммерческие предложения (КП), строит связанную БД и даёт удобный веб‑интерфейс (desktop + мобильный PWA) для поиска и работы.

## 2. Цели
- **Автоматизировать** ежедневный импорт/обновление данных из почты (инкрементально).
- **Извлекать** из писем/вложений контакты, организации и КП с высокой точностью (цель — 99%).
- **Структурировать** историю взаимодействий с ролями контактов по письму.
- **Предоставить** быстрый поиск (ФИО/телефон/email/город/организация/ИНН) и карточки сущностей.
- **Отслеживать** КП и срок их действия с напоминаниями.

## 3. Границы MVP (что входит / не входит)
**Входит:**
- Импорт писем/вложений (IMAP, STARTTLS), локальное хранение JSON писем и файлов вложений; опционально — сохранение `.eml`.
- OCR (локально + Google Vision для изображений/сканов).
- LLM‑извлечение: organizations[], contacts[], commercial_offers[] + бизнес‑контекст; роли контактов в письме.
- Постобработка: валидация → нормализация → дедупликация (включая маппинг локальных org_id → глобальные) → обогащение.
- Хранилище: **SQLite** (один файл `crm.db`) с возможностью миграции на Postgres.
- Веб‑интерфейс: поиск, карточки контакта/организации, реестр КП, уведомления о сроках КП, PWA.
- Экспорт в Google Sheets как промежуточный артефакт (лист «Контакты»/«Организации»/«КП»/«История»).

**Не входит в MVP:**
- Интеграции телефонии/WhatsApp, полные дашборды KPI — отложено на post‑MVP.
- Полнотекстовый поиск по телам писем — пока не требуется.

## 4. Пользователи и доступ
- Роли: **Администратор (вы)** и **Пользователь (жена)**, обе роли — с правом редактирования. Авторизация: Google OAuth2 или email+пароль (без 2FA на MVP).
- MVP работает локально (macOS), затем — перенос на VPS.

## 5. Критерии успеха
- **Точность извлечения ≥ 99%** (сомнительные — в модерационный inbox).
- Ежедневный инкрементальный запуск (CRON/Task Scheduler) и успешная обработка писем за прошлый день.
- Удобный поиск и карточки; корректные напоминания по истечению КП.

## 6. Риски и допущения (вкратце)
- Неуниверсально открыть письмо по Message‑ID в локальном клиенте (см. требования) — fallback: скачивание `.eml` и/или копирование темы/отправителя для ручного поиска.
- Вложения и почтовые тела разнообразны; OCR для сканов — обязательный компонент.
- Бюджет ограничен → максимальная опора на уже готовые скрипты и бесплатные компоненты.
